# تدقيق تنفيذ تحسينات Ouedna

## المتطلبات المؤكدة

التعديل ليس إعادة بناء. يجب الحفاظ على بنية Flutter الحالية، التنقل، Supabase، أسماء الجداول والأعمدة، RLS، Buckets، الخريطة الحالية، وهوية Ouedna العربية RTL. الأولويات: الاستقرار، الوظائف الموجودة، UX، الأداء، الأمان، ثم المزايا الجديدة.

## ما هو موجود فعلاً

- Flutter مع `supabase_flutter`, `flutter_map`, `geolocator`, `shared_preferences`, Firebase Messaging وLocal Notifications.
- مستودع الأماكن يستخدم Supabase مع طبقة cache محلية.
- الخريطة الحالية مبنية على `flutter_map`، وتعرض معالم قاعدة البيانات، وتملك تدفقاً داخلياً للملاحة الحية.
- خدمة الموقع موجودة وتطلب الصلاحية مباشرة عند الاستدعاء، وتحتاج رسائل تمهيدية وحالات هادئة.
- خدمة Firebase للإشعارات موجودة، لكنها تطلب إذن الإشعارات أثناء التهيئة مباشرة؛ يجب نقل الطلب إلى تفاعل أول تشغيل وعدم تكراره.
- مركز الإشعارات موجود ويدعم القراءة والربط إلى تحديث/معلم/رابط، لكنه لا يدعم حذف عنصر أو حذف الكل، وزر القراءة اسمه الحالي «قراءة الكل».
- الـBadge موجود ومبني باستخدام `PositionedDirectional`، ويجب الحفاظ عليه.
- شاشة الترحيب موجودة وهوية الصورة والشعار والألوان موجودة، لكن لا توجد ذاكرة لأول تشغيل ولا شاشة شرح الصلاحيات.
- موقع المرجع `https://ouedna.vercel.app` يعرض الأقسام: استكشف، الخريطة، ذاكرة الوادي، المجتمع، المفضلة، مخطط الرحلة، المساعد السياحي، ويحافظ على أسلوب Ouedna الصحراوي والبطاقات وRTL.

## القيود التنفيذية

- عدم إنشاء Supabase أو Backend أو جداول جديدة.
- عدم تغيير RLS أو API أو نظام الخريطة.
- حذف الإشعارات سيكون إخفاءً محلياً في SharedPreferences حتى لا تتأثر بيانات الإدارة أو بقية المستخدمين.
- طبقة الإشعارات ستبقى قابلة لربط Push الموجود، ولن تتم إضافة Backend جديد.
