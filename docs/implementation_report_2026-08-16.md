# تقرير تنفيذ تحسينات Ouedna

## النطاق والقرار المعماري

تم تنفيذ التحسينات داخل بنية Flutter الحالية للمشروع، مع الحفاظ على التنقل الحالي، هوية Ouedna العربية واتجاه RTL، Supabase، Firebase Messaging، Flutter Map، ومسار الملاحة الحية. لم تتم إعادة بناء التطبيق ولم تتم إضافة Backend أو قاعدة بيانات جديدة. مصدر المعالم وخطط الرحلة هو مستودع الأماكن المنشورة الحالي من Supabase، مع الاستفادة من الإحداثيات وساعات العمل والصور الموجودة في السجلات الحالية.

> «الأولوية هي: Stability ثم Existing functionality ثم UX ثم Performance ثم Security ثم New features ثم Visual polish.» — المتطلبات المرفقة.

## الوظائف التي تم تفعيلها

| المجال | ما تم تطبيقه |
|---|---|
| خط رحلتي | يختار المستخدم يوم الرحلة ووقت الانطلاق، ثم تُرتّب المعالم المنشورة الحقيقية حسب الاهتمامات والموقع والتقييم، وتظهر لكل محطة أوقات الوصول والمغادرة ومدة الزيارة والمسافة عن المحطة السابقة. |
| البيانات الحقيقية | لا توجد معالم وهمية في التخطيط؛ يعتمد الاختيار على الأماكن المنشورة ذات الإحداثيات من المستودع الحالي، وتعرض ساعات العمل المنشورة عند توفرها مع تنبيه للتحقق منها قبل الانطلاق. |
| المساعد السياحي | أُضيف مدخل واضح من الصفحة الرئيسية إلى صفحة المساعد الموجودة فعلاً، مع تمرير مستودع المساعد الحالي المتصل بـ Supabase Edge Function دون إنشاء مسار جديد. |
| التشغيل الأول | تُحفظ حالة مشاهدة شاشة الترحيب في SharedPreferences، فلا تظهر في كل تشغيل. بعد الدخول الأول تظهر نافذتا شرح الموقع والإشعارات مرة واحدة فقط. |
| GPS | أُضيف طلب صلاحية رسمي بعد شرح واضح، مع استمرار التصفح عند الرفض ورسائل هادئة عند تعطيل الموقع أو عدم توفره. لا يُشغّل التطبيق GPS في الخلفية إلا أثناء الملاحة الحية القائمة. |
| الإشعارات | أُبقي Firebase Messaging وLocal Notifications كما هما، ونُقل طلب الإذن من التهيئة التلقائية إلى تفاعل المستخدم بعد الشرح. |
| مركز الإشعارات | أضيف تحديد الكل كمقروء، حذف إشعار واحد، حذف الكل مع تأكيد، وحالة إخفاء محلية تحفظ بيانات Supabase دون تعديل. |
| إعدادات الإشعارات | أُضيف Toggle للإشعارات العامة. إيقافه يمنع إشعارات المحتوى العامة في الواجهة الأمامية، مع إبقاء إشعارات السلامة وتحديثات التطبيق الضرورية. |
| الخريطة | لم يتغير نظام الخريطة. أضيفت رسالة GPS بعد المحاولة، وتظهر المسافة من المستخدم وساعات العمل داخل بطاقة المعلم، مع بقاء زر بدء الملاحة الحية داخليًا. |
| الأداء والاتصال | استمر استخدام Cache الصور والمستودع المحلي الموجود، ولم تُضف طلبات GPS دائمة أو Backend جديد. تبقى حالات التحميل والخطأ وعدم توفر البيانات ضمن الواجهات الحالية. |

## الملفات المعدلة

| الملف | الغرض |
|---|---|
| `lib/app/ouedna_app.dart` | ذاكرة التشغيل الأول، شروحات الصلاحيات، إعدادات الإشعارات، وربط المساعد السياحي. |
| `lib/core/location/location_service.dart` | طلب صلاحية الموقع رسميًا ورسائل حالات الرفض أو تعطيل الخدمة. |
| `lib/features/compass/domain/itinerary_models.dart` | إضافة أوقات الوصول والمغادرة ومدة الانتقال إلى نموذج الرحلة. |
| `lib/features/compass/domain/compass_planner.dart` | إنشاء جدول يومي متتابع من المعالم الحقيقية وحساب المسافات ووقت الانتقال التقديري. |
| `lib/features/compass/presentation/compass_page.dart` | اختيار يوم ووقت البداية وعرض الجدول والمسافات وساعات العمل. |
| `lib/features/home/presentation/home_page.dart` | إضافة مدخل المساعد السياحي الموجود إلى الصفحة الرئيسية. |
| `lib/features/map/presentation/souf_map_page.dart` | حالات GPS وبطاقة المعلم والمسافة وساعات العمل. |
| `lib/features/notifications/data/ouedna_notification_service.dart` | تأجيل طلب إذن Push واحترام تفضيل الإشعارات العامة. |
| `lib/features/notifications/data/visitor_notification_repository.dart` | حفظ القراءة والإخفاء وتفضيل الإشعارات محليًا. |
| `lib/features/notifications/presentation/notification_center_page.dart` | الحذف الفردي والجماعي وتأكيد الحذف وتسمية القراءة المطلوبة. |
| `test/compass_planner_test.dart` | اختبار التوقيت المتتابع والمسافة إضافة إلى الاختبارات القديمة. |
| `docs/implementation_audit_2026-08-16.md` | سجل التدقيق الأولي والقيود التي تم احترامها. |

## ما لم يتغير

لم تتغير قاعدة البيانات أو أسماء الجداول والأعمدة أو RLS أو Buckets أو مفاتيح API أو نظام الخريطة أو صلاحيات Android الموجودة. حذف الإشعارات في التطبيق هو إخفاء محلي لكل جهاز، وليس حذفًا من جدول `visitor_notifications`، حتى لا تتأثر لوحة الإدارة أو المستخدمون الآخرون.

## اختبارات QA

| الفحص | النتيجة |
|---|---|
| `git diff --check` | نجح دون أخطاء مسافات أو مشاكل في الفرق. |
| علامات تعارض Git | لم توجد علامات تعارض في الملفات المعدلة. |
| الاستيرادات المكررة المتجاورة | لم توجد بعد المراجعة النهائية. |
| فحص نقاط الاستدعاء | تمت مراجعة منشئات `HomePage` و`CompassStop` وبطاقة الخريطة ومركز الإشعارات. |
| اختبار منطق المخطط | أضيف اختبار يثبت وجود وقت بداية، تتابع الوصول والمغادرة، وحساب المسافة. |
| `flutter analyze` | لم يُنفذ لأن Flutter SDK غير مثبت في بيئة الجلسة. |
| `flutter test` | لم يُنفذ للسبب نفسه؛ يجب تشغيله على جهاز التطوير أو CI قبل إصدار APK. |
| اختبار Android فعلي | لم يُنفذ داخل هذه الجلسة، ويظل مطلوبًا على جهاز Android حديث ومتوسط الإمكانيات. |

## ملاحظة مهمة على دقة التوقيت

الأوقات المعروضة في «خط رحلتي» محسوبة من الإحداثيات المنشورة، وسرعة انتقال تقديرية داخل المدينة، ومدة زيارة افتراضية قدرها 75 دقيقة. أما ساعات العمل فتظهر من النص المنشور للمكان عند توفره؛ لذلك يجب التحقق منها قبل الانطلاق، لأن قاعدة البيانات الحالية تخزنها كنص حر وليست كجدول زمني منظم. لم تتم إضافة ادعاءات عن الطقس أو الازدحام أو الحجوزات لأنها ليست مصادر متاحة في المشروع الحالي.
